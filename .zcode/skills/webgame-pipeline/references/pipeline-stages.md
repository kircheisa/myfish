# Pipeline Stages — 规划、文档协议与校准

改编自 Godogen 文档协议 + game-design-skills 校准法。核心：**状态进文件，不进对话**——上下文被压缩/跨会话后，读文件即可续做。

## 风险分解（Decomposer 哲学）

反直觉但重要：**不要把一切拆成小任务**。每个任务边界都是集成风险，边界越多 bug 越多。

分类标准：
- **常规功能**（一份批量任务做完）：UI、数值调整、动画、采集物、生物行为微调、文案——引擎/现有管线已验证能兜住的东西。
- **高风险任务**（单独隔离，先做先验证）：地形/高度场改动、着色器、物理/移动模型、架构级重构（状态机、存档 schema）、性能敏感路径。

每个高风险任务必须有**独立验证标准**（怎么证明它对了——数值采样？截图对比？帧率阈值？），写进 PLAN.md。

## docs/PLAN.md 模板

```markdown
# PLAN — <功能名>（日期）

## 目标
一句话 + 用户原话。

## 任务
### T1 高风险：xxx
- 状态: pending | doing | done | blocked
- 验证: <可执行的判据，如"node 采样岛心高度 ≈ +9；陆地占比 ~29%">

### T2 常规批量：xxx / yyy / zzz
- 状态: pending
- 验证: 视觉 QA 清单（HUD 无重叠 + 程序化断言）

## 回归清单（动到核心系统时）
- [ ] 捕鱼→订单→连击→成就链
- [ ] 潜水 O2 分档 / 登岛三态
- [ ] 存档读写 / 清档重置
```

规则：每完成一任务立即更新状态 + git commit（commit message 引用任务号）。

## docs/MEMORY.md 惯例

追加式日志，新发现写顶部：

```markdown
## <日期> — <主题>
- <坑/发现/决策 + 一句原因>
```

与 quirks.md 的分工：MEMORY 是过程记录；**确认可复用的坑升格进技能的 quirks.md**（技能随 git 走，下个项目也带上）。

## 平衡校准（加倍/减半法）

调数值别凭感觉小修小补：对 drain/概率/速度做 **2x 或 0.5x** 极端对照——
- 变化明显 → 该变量重要，值得精调
- 变化不大 → 别再花时间
- 暴露新问题 → 重新设计这条数值线

体验节奏目标（本游戏）：单次生存需求 3~4 分钟一遇，不打断捕捞核心循环；注意力 7~10 分钟一档。

## 会话恢复

新会话接手旧工作时：
1. 读 `docs/PLAN.md`——有 doing/blocked？从那里继续
2. 读 `docs/MEMORY.md` 顶部几条
3. 读本技能 `references/quirks.md`
4. 探活服务器后直接进入执行，不重做已完成规划
